# 文件命名约定

## 1. 目的

为了对项目中的各类文档（尤其是硬件元器件的数据手册）进行统一、清晰、可读性强的管理，特此制定本文件命名约定。

## 2. 命名规则

所有文档均采用以下格式进行重命名：

`[文档类型]-[功能/主题]-[厂商]-[型号].pdf`

命名所需信息（如功能、厂商、型号）优先从文件名中提取。如果文件名信息不足，则通过读取文档内容来获取。

### 2.1 字段说明

*   **[文档类型]**: 文档性质的缩写。
    *   `DS`: **Datasheet** (数据手册) - 器件的核心技术规格。
    *   `AN`: **Application Note** (应用笔记) - 关于器件具体用法、特定场景解决方案的文档。
    *   `UG`: **User Guide** (用户指南) - 模块或产品的用户手册。
    *   `PS`: **Product Specification** (产品规格书) - 通常指产品的功能、性能列表。
*   **[功能/主题]**: 简要描述器件的核心功能或文档的主要内容。
    *   *示例*: `Temperature and Humidity Sensor`, `Wi-Fi BLE MCU`, `Apex Motion Functions`
*   **[厂商]**: 组件或芯片的制造商。
    *   *示例*: `ASAIR`, `Espressif`, `TDK`
*   **[型号]**: 组件或芯片的具体型号。
    *   *示例*: `AHT30`, `ESP32-S3`, `ICM-42607x`

### 2.2 示例

*   **原始文件名**: `AHT30.pdf`
*   **格式化后**: `DS-Temperature and Humidity Sensor-ASAIR-AHT30.pdf`

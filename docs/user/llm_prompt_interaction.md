# LLM 提示词交互机制解析 (LLM Prompt Interaction Principle)

本文档旨在解释设备端如何利用 **Prompt Injection (提示词注入)** 技术，在不修改二进制通信协议的前提下，实现复杂的隐式交互（如“拍一拍”功能）。

## 1. 核心机制：Prompt Engineering 作为协议

传统 IoT 开发通常需要定义严格的二进制协议（例如：`CMD_TAP_DETECTED = 0x01`），然后服务器端编写专门的代码来解析该指令并生成回复。

但在 Agent 时代，我们可以利用 **LLM (大语言模型)** 强大的语义理解能力，将“协议”软化为“自然语言”。

### 示例场景
*   **物理事件**: 用户拍打了设备 (Tap)。
*   **设备行为**: 发送文本 `[System Event: User Tapped] 请回复：别拍了，我在！`。
*   **云端行为**: 将该文本直接输入给 LLM。

---

## 2. LLM 能看懂吗？(Can LLM Understand?)

**答案：能，且非常擅长。**

*   **标记习惯**: 方括号 `[]` 在大模型的训练语料中，常被用作“系统旁白”、“舞台指示”或“状态描述”。
*   **语义解析**: 
    *   LLM 不会把这句话当成用户说出的“System Event...”。
    *   LLM 会将其理解为：**“系统告诉我发生了一个物理事件，并指示我扮演特定角色进行回应。”**
*   **无需注册**: 不需要预先在服务器注册“Tap 事件”。只要该事件能用自然语言描述清楚，LLM 就能处理。

**优势**:
*   **灵活性**: 如果想改回复风格（例如变得更傲娇），只需修改设备端发送的 Prompt 文本，无需升级服务器代码。
*   **扩展性**: 新增手势（如“摇一摇”）时，只需发送 `[System Event: User Shook Device] ...`，服务器端零适配成本。

---

## 3. 云端识别原理 (Cloud Recognition)

小智云（或通用 LLM 后端）是如何识别并处理它的？

*   **通道层 (Transport)**: 
    *   在 MQTT 或 WebSocket 协议层面，设备调用 `SendText()`。
    *   服务器接收到的是标准的 JSON 消息 `{"type": "listen", "text": "..."}` 或纯文本。
    *   对于服务器而言，这等同于“用户通过键盘输入了一行字”或“语音识别转出的文字”。

*   **应用层 (Application)**:
    *   服务器没有特殊逻辑去拦截 `[System Event]`。
    *   文本直接进入 LLM 的 Context (上下文)。
    *   **LLM 才是真正的协议解析器**。它读懂了 Prompt，并执行了指令（生成语音回复）。

---

## 4. 协议定义归属 (Protocol Taxonomy)

这种交互方式不属于传统的 **传输协议 (Transport Protocol)** 定义，而是属于 **交互协议 (Interaction Protocol)** 或 **提示词协议 (Prompt Protocol)**。

| 层面 | 协议示例 | 本功能中的角色 |
| :--- | :--- | :--- |
| **传输层** | MQTT, TCP/IP | 负责将字符串完整送到服务器 |
| **会话层** | WebSocket JSON | 定义这是“一段文本”而非“音频流” |
| **语义层** | **Prompt Engineering** | **定义这段文本代表“拍打事件”而非“用户说话”** |

### 总结
这是一种利用大模型能力的“降维打击”技巧。通过将物理信号转化为自然语言 Prompt，我们将复杂的嵌入式开发工作（定义协议、联调接口），转化为了简单的提示词编写工作。只要云端支持文本对话，设备端就能拥有无限的交互可能性。
